# 发布新版本

## 1. 准备安装包

构建并测试插件，确认版本号、文件名和目标平台。安装包不要直接提交到 Git 仓库。

## 2. 创建 GitHub Release

在仓库的 **Releases** 页面创建标签，例如 `plugin-name-v1.2.0`，填写版本说明并上传安装包。

如果多个插件共用本仓库，建议为标签添加插件名前缀，避免版本号冲突。

## 3. 更新站点内容

1. 更新对应的插件页面和下载链接。
2. 更新对应的日志页面。
3. 在插件列表中更新最新版本。
4. 提交并推送到 `main`。

## 4. 等待自动部署

GitHub Actions 会自动构建并部署网站。可在 **Actions** 页面查看进度。

::: tip 稳定下载链接
固定版本建议直接链接对应 Release。只有整个仓库始终发布同一个插件时，才适合使用 `releases/latest`。
:::
